It cannot. The winner is decided by how the equations treat each layer: Intellect is simulated as handing the AI the true data, and quantum ties an ordinary solver 94% of the time.

The recipe

Five steps, using the page's default run

Default run: problem Ambulance base coverage, model Claude Sonnet 5.5, 8 yes/no decisions (so 256 possible answers). Every number below is recomputed from the code.

1 · A puzzle with a known best answer

cost of an answer z = c + Σ Qii·zi + Σ Qij·zi·zj (z is 8 yes/no choices) score = 0 if the answer breaks a hard rule score = (worst allowed − yours) / (worst allowed − best) otherwise

The page tries all 256 answers, so it always knows the true best one. That best answer is the 100% line. Break a rule and you get 0% however good the rest looks.

2 · The “AI”: two dials and some random noise

noise σA = 0.6 × (1 − cap) + gap = 0.6 × (1 − 0.91) + 0.12 = 0.174 (shown: 17%) rules remembered cA = cs × privacy = 0.66 × 0.35 = 0.231 (shown: 23%) AI's version of the puzzle = truth + random noise × σA + only cA of the rule penalties

cap and cs are numbers typed into the code for each model (Sonnet 5.5 gets 0.91 and 0.66). gap and privacy are typed in per problem. The AI then answers by picking one choice at a time on its own distorted puzzle. No model is asked anything.

3 · “Intellect”: the AI is handed the true data

cut = min(0.92, match × (0.5 + 0.2·feedback) + 0.1·u + from-files) = 0.5 + 0.033 = 0.533 noise after Intellect σI = σA × (1 − cut) = 0.174 × 0.467 = 0.081 (shown: 8%) rules known cI = cA + (1 − cA) × min(1, know + curiosity…) = 1.00 (shown: 100%)

If the knowledge pack matches the problem, match = 1 and noise is roughly halved. The rule-memory jumps to the maximum. The “calibration” step goes further: terms the AI is unsure about are replaced with the true values. So “Intellect” here means “someone gives the AI the answer key”, which is why it helps every model.

4 · “Quantum”: a real but small simulation

fidelity F = (1 − e2)^n2 × (1 − e1)^n1 × (1 − ro)^n = 0.9988^144 × 0.99997^128 × 0.9985^8 = 0.828 after readout fix Fe = F / (1 − ro)^n = 0.838 what is measured: P(z) = Fe × P_ideal(z) + (1 − Fe) / 256 (then 1,024 samples are drawn)

This part is genuine maths: an 8-qubit quantum circuit (QAOA) simulated on an ordinary CPU, with a noise formula for a trapped-ion machine. It then keeps the best of 1,024 samples as judged by the AI's own version of the puzzle. The circuit settings are tuned using the simulator's exact probabilities, which a real machine could not do for free.

5 · The fair check: an ordinary solver

simulated annealing: 4 restarts × 256 steps = 1,024 tries, on the same puzzle version

With only 256 possible answers, 1,024 ordinary tries almost always find the best one. That is why the page often says “the quantum part was not what made the difference”.

What to say, and what would make it a real test

A fair description and a short list of fixes

Fair description: “A working demonstration of how a knowledge layer and a quantum search could combine, using a simplified model of AI errors. The AI errors are assumptions, not measurements.”

To make it a real test: (1) send the same puzzles to real models and measure their actual formulation errors, (2) give the Intellect layer only information a real user could supply, not the true values, (3) report quantum versus classical only on problems too large to enumerate, (4) run on real hardware or with published error rates and no free tuning.

Method: the simulator's maths was extracted unchanged from your saved HTML (not my localhost copy) and run in Node with no network. It reproduced the on-screen run log exactly, and all 120 numbers in the built-in qualification table (4 models × 15 problems × 15 instances) to four decimals. Sweep: 37 models × 15 problems × 10 instances, seeds 1000 + 7919·k, using the page's own default settings and its own qualification setup. Code and data are in the repo under xlab/analysis/. Model names come from the page; I have not verified that they exist.
